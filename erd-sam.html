ERD itu pakai tipe data nggak sih?

jawaban singkat
Conceptual / Ringkas — tanpa tipe
Cuma nama_tabel — atribut — PK/FK. Cocok buat laporan PBL, slide sidang, poster. Bersih, gak bikin tabel warna-warni.
produk { id_produk PK, nama_produk, id_kategori FK }
Physical / Lengkap — pakai tipe
Tambah bigint / string / int / date / enum persis dari migration. Cocok buat lampiran teknis / dokumentasi DB.
produk { bigint id_produk PK, string nama_produk, int stok_gudang }
Rekomendasi buat lu: pakai Mode Ringkas (tanpa tipe) di bab laporan. Tipe data taruh di lampiran aja. Dosen nggak protes — malah lebih rapi. Di file ini gw sediain keduanya, tinggal copy yang lu butuh.
bigint = angka bulat besar (ID) string = teks pendek (varchar) int = angka bulat date/datetime = tanggal enum = pilihan tetap boolean = ya/tidak json = data fleksibel

Arti label di garis — "berisi, dirinci, dilacak" itu apa?

Itu kata kerja relasinya — dibaca searah panah. Contoh: transaksi ||--o{ detail_transaksi : berisi dibaca "1 transaksi BERISI banyak detail_transaksi". Bukan nama kolom, cuma biar diagram bisa diceritain ke dosen.
